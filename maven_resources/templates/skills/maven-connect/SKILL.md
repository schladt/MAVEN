# Connect cloud memory

Use installed `maven-memory`; never implement an alternate transport or rely on the source checkout's Python environment. Instance settings default to `~/.maven/.env`, or `$MAVEN_HOME/.env` when explicitly selected. `--env PATH` overrides the file. Settings must be owner-owned regular files with mode `0600`; parse literals only, never shell-source them.

Select the project explicitly. Read `maven-project show --root ROOT` and use its project UUID in `maven-memory --format agent context --project-id UUID`, adding applicable `--workflow` or `--operation`. There is no global current project. For normal lifecycle start with `maven-start-work --root ROOT --harness NAME`; retain the returned durable session UUID for every subsequent lifecycle command. Use `--harness-session ID` when the harness exposes a session identity. A resumed session must be explicitly selected; do not infer it from a checkout or transcript.

Context is a complete authority load, not a search result. Read all applicable approved pages and exact transitive dependencies. Hash, revision, generation, compatibility, revoked or missing authority failures block action. Never substitute local remembered instruction bodies or historical transcripts.

If selected login is unavailable or expired, stop cloud operations. Ask the owner to complete normal interactive AWS login using the exact configured profile and private login-cache directory. Do not print other settings, capture credential output, auto-login, change identity or elevate. Retry only after the owner finishes login. Missing settings require maven-setup, not guessed locators.

`--format json` returns complete JSON. `--format agent` returns `maven-lossless-tree-v1`: strings are ordered chunks, objects encoded ordered key/value entries, arrays encoded items, and scalars unchanged. Concatenate all string chunks exactly. Read every range of captured output when tool display limits truncate it; do not repeatedly fetch cloud pages merely to obtain their display. Never summarize authority before fully reading it.

Checkpoint and stop use explicit root and session. They require applicable approval before Git publication, never silently pull or switch branches, and must preserve unknown-outcome receipts. Closing one session must not revoke shared login while peers remain active. No prior project handover is normal for a new project; do not invent one.
