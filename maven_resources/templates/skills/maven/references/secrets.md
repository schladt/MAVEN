# Explicit secret and encrypted-file usage

Use only the configured store, account, region and namespaces. Never guess or adopt a bucket, wrapping key or parameter. On a host without store locators, the first `maven_secrets`/`maven-secrets` use binds the account's one existing store from its own verified description; nothing is created or granted. If that stops, relay its next step (usually `maven-setup --repair-secrets`). This procedure covers usage, not scanning, importing or provisioning resources. Installing or updating this guide does not activate, revoke or change the separate cloud policy or its adapter dependencies.

This installed usage guide does not authorize access to any secret or consumer. Check the owner's intent and use the separate secret tools and their actual schemas. Ordinary project memory, including a setting or a project skill, is not a secret catalog, approval or grant.

**Fresh instance:** ordinary memory needs no cloud instructions. Secret catalog writes and approved consumers deliberately fail closed without an owner-approved `maven-secrets` security policy. Do not interpret a missing or revoked policy as permission. If the owner explicitly wants to enable these optional operations, use the selected installation's internal `python -m tools.memory.cli --env <private-environment> instruction` helper; the owner does not operate a CLI. Read the existing `maven-secrets` page first. Never replace an existing policy or its dependencies when enabling a different project.

For a confirmed absent page, prepare an owner-scoped (`data_scope: owner`, `classification: Sensitive`) `draft` with stable request/proposal/page UUIDs, `expected_revision: 0`, actual owner `source` and `change_reason`. The candidate is `page_kind: skill`, `slug: maven-secrets`, `title: MAVEN secret usage`, `scope: {}`, `authority_state: active`, and `body_markdown` containing the complete installed usage policy the owner is reviewing. It needs no retired workflow/maintenance pages. Validate the private JSON offline with `draft <file> --validate`, then submit the exact draft only on explicit request. Read the full stored proposal with `read --proposal-id`, obtain its `challenge --proposal-id` through the separate approval role, and show its complete content, instance, scope and hash. Only an actual owner approval authorizes `activate <private-resolution-file> --confirm-candidate <hash>` with that proposal, challenge, hash, expected revision, real approval source and stable request key. Read back with `load --slug maven-secrets`. Do not auto-approve, auto-renew or guess after an uncertain write. Enabling this policy does not authorize any adapter definition, grant or individual secret disclosure.

With the actual `cwd` and an enabled project (or explicit Home selection), use `maven_secrets(action="list", ...)` for paged names/metadata only; `domain` is a dotted namespace filter. `lookup` with an exact `name` reads only that Home secret setting, not general memory search. Never return plaintext values to the model.

An explicit owner request to `store_and_catalog` supplies the nonsecret name, actual request `source` and owner-private `source_path`, never the secret itself in tool arguments, argv or environment. Select `ssm` or `encrypted-file`; `replace=true` means intentional rotation. The catalog entry is a separate security operation: do not create a project-memory copy or bypass missing Home/store configuration.

Storage receipts and catalog completion are distinct. References pin SSM versions or immutable encrypted-file objects. File rotation creates a new object and compare-and-swaps the logical pointer against the prior catalog revision. Storage and catalog changes are not an atomic provider credential rotation. If storage succeeds but catalog is pending, preserve the original operation ID and use `retry_catalog`; never re-upload to repair the catalog. Preserve uncertain outcomes.

Standalone `maven-secret-catalog store-and-catalog NAME --input PRIVATE_PATH` (or `--stdin`) and `lookup NAME` / `retry-catalog OPERATION_ID` implement the same sessionless catalog flow. Low-level `maven-secrets list --domain DOMAIN`, `put`, `replace`, `check`, `get`, and `file put/get` never write Home. Use hidden terminal entry or a trusted pipe for values. `reveal NAME --tty` requires explicit owner disclosure intent. Trusted local programs, including those without a terminal (agents, SSH, launchd), read with `maven-secrets get NAME | trusted-program` (stdout must be a pipe or file; exact value, no newline) or `use-stdin NAME -- trusted-program`, and write with `trusted-program | maven-secrets put|replace NAME --stdin`. The recipient can disclose plaintext; never capture `get` output in a transcript, log, argv or environment.

For bounded binary streams use `maven-secrets file put NAME --stdin --max-bytes LIMIT --json`; input is encrypted without plaintext spooling. File restore refuses an existing path and creates private plaintext: choose a private parent and disposition. Protect wrapping keys separately from ciphertext. Encryption does not authorize upload/sharing, and attempted upload never authorizes deleting keys or originals.

Use `maven_secret_adapter` for owner-defined declarative consumers: approved executable/argument templates, stdin or private-FD delivery, and explicitly nonsecret results. Definitions and standing/single-use grants are cloud-approved authority, not editable catalog settings. Read policy; prepare the exact invocation; present complete proposal reviews/challenges and obtain real approval. Drafts and grant documents are not approvals. Single-use grants pin the invocation/digest and expiry and are consumed atomically across hosts. Missing/stale authority fails closed; uncertain consumption/execution must not be replayed.

Never expose raw adapter stdout/stderr or secrets in transcripts, cloud notes or Git. Only declared nonsecret results may return. An adapter is not a sandbox against trusted-executable misuse; review its actual destination, inputs and effects. Google is not a core adapter/runtime. Existing Google credentials remain ordinary SSM values; independent Magic Workspace is unaffected.
