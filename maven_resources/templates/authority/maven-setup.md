# Explicit owner-reviewed installation and setup

Run `python3 install.py` from a reviewed public checkout for guided first-time setup; no preexisting virtual environment or project `.maven` is needed. It creates local isolated code and private configuration, then invokes the installed `maven-setup` wizard. `--local-only` omits that wizard. Installation itself does not authorize cloud spending, deployment, login, Google consent or global harness changes. Explain the selected instance home and optional harness destinations; require affected harness shutdown before copying skills. Preserve existing configuration and refuse conflicting skills.

Use the selected home's installed commands (`activate`, never `.env`, supplies shell PATH). Resume instance setup with `maven-setup`; preserve private runtime/setup artifacts, exact request identities and unknown-outcome receipts. Existing-instance import or selected-stack binding must never deploy, reinitialize a database or replace active authority. New-instance setup requires separate explicit approvals for change-set creation, exact reviewed execution, initialization and each starter candidate. Install/connect an instance once; the project step can be deferred after verified cloud access and complete authority. Report instance readiness separately from project readiness. Normal OMP use is to open the intended project and invoke `/skill:maven-start-work`; no terminal lifecycle ritual or user-generated UUIDs are required.

Confirm an absolute project root independently of tool installation; reject `/` and ask about ambiguous/subdirectory roots rather than silently changing the binding. The MAVEN source checkout is a project only after explicit owner selection. Use `maven-project setup --root ROOT` for guided project setup. An agent first obtains all owner choices in chat, then passes `--non-interactive` with either `--project-id UUID` or `--create --name NAME --source-origin ORIGIN --source-excerpt EXCERPT`, plus either `--no-git` or all of `--remote REMOTE --accepted-url URL --branch BRANCH`. Git detection proposes actual checkout/remote/push URL/branch for confirmation without mutation. Creation requires genuine source evidence; missing choices fail before a cloud write.

Setup generates and journals project/request UUIDs before mutation. Keep per-root private ignored `.maven/runtime` receipts and preserve exact legacy instance-wizard pending/saved requests. Reconcile original IDs before explicit resumed mutation; never discard uncertainty or mint another project. Existing configured-project setup preserves and validates its selection. Additional projects must not reuse the instance wizard's saved first project as their pointer. Setup never commits, pushes, pulls or switches branches.

Before cloud provisioning, establish the owner-selected AWS account, region, named profiles, least-privilege roles, resource names, allowed source network, project and budget. Use packaged infrastructure and the shipped deployment preparation command. Review the exact generated template, policy, package digest, capabilities, parameters and cost-bearing resources with the owner. Apply only the reviewed artifact and matching confirmation value using the explicitly selected setup profile. Do not broaden permissions or open network access to make setup pass.

Keep deployment credentials separate from runtime credentials. Record private outputs only in the owner-private environment. Bind the actual caller through the reviewed IAM role trust and preexisting owner-approved assume-role grants. Use `maven-memory install init --confirm-instance UUID` to initialize the exact selected service and verify runtime access. Project selection is a separate optional setup step, not privilege enrollment. No example identifier is a valid configuration value.

Prepare starter proposals locally, review each body and dependency, and submit only owner-approved candidates. Request and preserve real activation challenges and exact owner approval evidence. Activate dependencies first. Installation and proposal generation must never auto-activate authority. Google and file-secret stores require separate explicit setup; they are not prerequisites for core memory.
