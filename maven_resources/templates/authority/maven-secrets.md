# Explicit secret and encrypted-file usage

Use only the explicitly configured store, account, region and namespaces. Never guess or adopt a bucket, wrapping key or parameter. This skill governs usage, not scanning, importing or provisioning resources.

In configured Read Only, Home or project mode, discover approved instructions with `maven_instructions`, then load this skill and its governing dependencies with `maven_context(skill_slug="maven-secrets")`. Discovery alone is not authority. Off/unconfigured modes deny access. Named loads do not initialize sessions or capture discussion; Read Only loads universal authority, while bound loads preserve actual project scope.

Use `maven_secrets(action="list")` for paged names/metadata only; `domain` is a dotted namespace filter. `lookup` with an exact `name` reads only that Home secret setting, not general memory search. Never return plaintext values to the model.

An explicit owner request to `store_and_catalog` supplies the nonsecret name, actual request `source` and owner-private `source_path`, never the secret itself in tool arguments, argv or environment. Select `ssm` or `encrypted-file`; `replace=true` is intentional rotation. This may write exactly one secret catalog setting into the configured Home from Read Only or another project without rebinding, a Home session, other memory writes, search or capture. Missing Home/store selection fails closed.

Storage receipts and catalog completion are distinct. References pin SSM versions or immutable encrypted-file objects. File rotation creates a new object and compare-and-swaps the logical pointer against the prior catalog revision. Storage and catalog changes are not an atomic provider credential rotation. If storage succeeds but catalog is pending, preserve the original operation ID and use `retry_catalog`; never re-upload to repair the catalog. Preserve uncertain outcomes.

Standalone `maven-secret-catalog store-and-catalog NAME --input PRIVATE_PATH` (or `--stdin`) and `lookup NAME` / `retry-catalog OPERATION_ID` implement the same sessionless catalog flow. Low-level `maven-secrets list --domain DOMAIN`, `put`, `replace`, `check`, and `file put/get` never write Home. Use hidden terminal entry or a trusted pipe for values. `reveal NAME --tty` requires explicit owner disclosure intent. `use-stdin NAME -- trusted-program` delivers plaintext to a trusted recipient, which can disclose it.

For bounded binary streams use `maven-secrets file put NAME --stdin --max-bytes LIMIT --json`; input is encrypted without plaintext spooling. File restore refuses an existing path and creates private plaintext: choose a private parent and disposition. Protect wrapping keys separately from ciphertext. Encryption does not authorize upload/sharing, and attempted upload never authorizes deleting keys or originals.

Use `maven_secret_adapter` for owner-defined declarative consumers: approved executable/argument templates, stdin or private-FD delivery, and explicitly nonsecret results. Definitions and standing/single-use grants are cloud-approved authority, not editable catalog settings. Read policy; prepare the exact invocation; present complete proposal reviews/challenges and obtain real approval. Drafts and grant documents are not approvals. Single-use grants pin the invocation/digest and expiry and are consumed atomically across hosts. Missing/stale authority fails closed; uncertain consumption/execution must not be replayed.

Never expose raw adapter stdout/stderr or secrets in transcripts, cloud notes or Git. Only declared nonsecret results may return. An adapter is not a sandbox against trusted-executable misuse; review its actual destination, inputs and effects. Google is not a core adapter/runtime. Existing Google credentials remain ordinary SSM values; independent Magic Workspace is unaffected.
